# UX 재조사 — 왜 이전 5종이 전부 실패했는지

**결론부터.** 이전 목업은 유튜브 **시청 제품**(홈, 채널, 워치, 쇼츠, TV)을 우리 제품에 씌운 분장이었다. YouTube Insight는 영상을 보는 앱이 아니라, 크리에이터가 **급등 순위를 보고 → 검색 문구를 고르고 → Deep Search 하는 조사 도구**다. 메타포가 틀리면 톤·밀도·모션을 아무리 키워도 별로가 된다.

Mobbin은 유료/`needsAuth`라 쓰지 않았다. 대신 **실제 작업 화면**만 봤다: YouTube Studio(콘텐츠·Advanced Mode), vidIQ/TubeBuddy 키워드 워크플로, Google Trends Explore, 우리 `studio.html`의 실제 Job.

---

## 1. 사용자가 하는 일 (Job)

스튜디오에서 반복되는 일은 세 가지뿐이다.

| 순서 | Job | 지금 제품의 조작 |
|------|-----|------------------|
| A | 지금 KR에서 뭐가 터지나 본다 | 카테고리 → 티커/순위 모달 |
| B | 그 제목에서 **검색창에 넣을 문구**를 고른다 | 황금키워드 칩 |
| C | 그 문구로 검색한다 | `#keyword` + Deep Search |

성공은 “유튜브처럼 보이는가”가 아니다. **A→B→C가 한 화면에, 헷갈리지 않고, 엄지가 덜 움직이게** 끝나는가다.

페르소나 (PRD와 동일):

- 노트북 작업 크리에이터: 순위 표와 숫자를 비교하고, 칩을 눌러 검색한다.
- 폰 작업 크리에이터: 칩 → 검색 → 결과 1열.
- 방문 크리에이터: 공개 보드는 이 문서 범위 밖. 스튜디오와 톤만 맞춘다.

## 2. 이전 5종이 깨는 휴리스틱

Nielsen의 해당 항목만 적는다.

| 휴리스틱 | 이전 목업이 한 일 | 실제 사용자에게 |
|----------|-------------------|-----------------|
| 시스템-세상 일치 | 구독, 좋아요, 쇼츠 사운드, 12.8만 구독자 | 우리 제품에 없는 기능. 거짓 어포던스 |
| 심미·최소 | 히어로 포스터, LIVE 펄스, 가짜 썸네일 그라데이션 | 조사에 필요 없는 시각 소음 |
| 기억보다 인식 | 검색창과 키워드가 서로 다른 화면에 숨음 | “다음에 뭘 누르지?” |
| 일관성 | 5종이 5개 다른 제품 | 학습 비용만 늘음 |
| 에러 예방 | 티커·구독·재생이 비슷하게 빨강 | 순위와 검색이 다시 섞임 |
| 유연성 | 쇼츠 월·시어터만 강요 | 표로 비교하고 싶은 파워 유저 무시 |
| 상태 가시성 | 가짜 LIVE 배지 남발 | 진짜 데이터 갱신과 구분 안 됨 |

시각적으로도 실패 이유가 같다.

- 64px 영화 제목은 도구 UI가 아니다. YouTube Studio·vidIQ 웹은 **표, 필터, 작은 썸네일, 작은 타이포**.
- 무지개 그라데이션 카드는 “썸네일 없음”이지 완성된 UI가 아니다.
- 액센트가 빨강+금+파랑+글로우로 싸워 PRD의 “액센트 한 색 + 황금만 앰버”를 어겼다.

`studio.html` 현재 화면도 같은 병을 조금 갖고 있다: 이모지 남발, 보라 그라데이션 AI 버튼, 검색줄에 CTA가 한 줄로 과밀. 목업이 그걸 엔터테인먼트로 키운 것이다.

## 3. 벤치마크에서 가져올 것 / 버릴 것

### YouTube Studio (콘텐츠, Advanced Mode)

가져올 것: 왼쪽(또는 상단) **필터가 고정**, 본문은 **표**, 행을 찍으면 세부. 차트는 숨길 수 있음. 검색은 타이틀 필터. 액센트 빨강은 로고·위험만.

버리지 말 것: 홈 피드, 채널 배너, 워치 플레이어, 쇼츠 풀스크린. 그건 시청 제품이다.

### vidIQ / TubeBuddy

가져올 것: **키워드가 검색 옆에 붙어 있다.** 사이드바/인스펙터. VPH·기여도 같은 숫자 한 줄. “점수를 보여주고 다음 행동을 버튼으로”.

버리지 말 것: 확장프로그램 오버레이 전체를 우리 정적 페이지에 복제하기. 우리는 BYOK 웹 스튜디오다.

### Google Trends Explore

가져올 것: **검색이 본체.** 관련 질의는 옆 패널. Rising vs 일반을 표로. 비교는 나중에 Should.

버리지 말 것: 검색량 그래프를 가짜로 그리기. 우리 황금키워드는 search volume API가 아니라 **급등 제목 n-gram**이다. UI가 그 정체를 숨기면 안 된다.

## 4. 편의성 원칙 (이번 목업의 불변)

1. **검색창은 항상 보인다.** 히어로 뒤로 보내지 않는다.
2. **황금키워드는 검색창 반경 안에 있다.** 스크롤 보물찾기 금지. (금색 버튼은 “그 칩으로 포커스”만.)
3. **순위와 검색은 시각적으로 다른 가족.** 빨강/표 = 순위. 앰버 칩 = 검색어. 둘 다 큰 빨간 알약이 아니다.
4. **숫자는 표로 비교**할 수 있어야 한다. 기여도·VPH는 장식이 아니라 정렬 단서.
5. **한 화면 한 주요 CTA:** Deep Search. 나머지는 보조.
6. **카피는 조작을 말한다.** “구독하는 대신 순위” 같은 말장난 금지. “지금 카테고리 영상 20” / “이 문구로 검색”.
7. **터치 44px, 포커스 링, Esc로 모달 닫기, `/`로 검색 포커스.**
8. **폰은 아래가 검색.** 엄지 존. 헤더에 API 키를 풀너비로 쌓지 말고 접는다.
9. **빈 상태·선택 상태**를 만든다. 행을 고르면 인스펙터가 바뀐다.
10. **가짜 소셜 프루프 금지.** 구독자 수, 좋아요, LIVE 시청 1.2만은 우리 데이터가 아니다.

## 5. 새 5종은 “스타일”이 아니라 “작업 순서”

같은 데이터, 같은 CTA 계약, **다른 정보 구조**다. 색만 바꾸거나 유튜브 화면만 바꾸지 않는다.

| # | 이름 | 누구에게 | 한 줄 |
|---|------|----------|--------|
| 1 | **워크벤치** | 매일 노트북 | 표에서 고르고, 오른쪽에서 검색어를 누른다 (메일/vidIQ) |
| 2 | **검색 우선** | 키워드가 이미 있는 사람 | Google처럼 검색이 본체, 칩은 자동완성 |
| 3 | **오늘 브리핑** | 아침에 뭐가 터졌나만 | 토픽 행마다 검색/순위가 갈린다 |
| 4 | **콘텐츠 표** | 숫자 비교 | YouTube Studio 콘텐츠 페이지처럼 필터+표+드로어 |
| 5 | **엄지 스택** | 폰 | 칩 → 리스트 → **하단 고정 검색** |

권장 기본값은 **1 워크벤치**(데스크톱) + **5의 하단 검색**(폰 규칙). 2~4는 취향·숙련도 대안이다.

로컬: `./run-local.sh docs/mockups/work-five.html`

이식할 때는 고른 1개의 IA만 `studio.html`에 넣는다. 5개를 동시에 제품에 넣지 않는다.
